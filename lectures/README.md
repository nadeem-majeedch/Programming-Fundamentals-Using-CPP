## Status

✅ **All 32 lecture planning files are authored.** Each is a complete teaching
plan (not student handout): objectives, prerequisites, concept sequence,
teaching topics, required examples, misconceptions, activity, exercises,
exit ticket, and time allocation.

## Planning-file template (what every lecture file contains)

1. **Header** — module, week, global lecture number, duration, outcomes
   (`CLO-x` · `PF-m.n`).
2. **Learning objectives** — 3–4 numbered, measurable, tied to PF codes.
3. **Prerequisites** — exact lectures/modules assumed.
4. **Concept sequence** — the 5–6 step narrative arc.
5. **Teaching topics (detailed)** — the actual content, with specified
   examples, idioms, and demo beats. No placeholder text.
6. **C++ examples required** — files in [../examples/](../examples/README.md)
   (with live-typed demos named).
7. **Common student misconceptions** — named, with the counter-teaching.
8. **Classroom activity** — a concrete 15–25 min exercise.
9. **Practice exercises** — core set + 🟡 stretch.
10. **Exit ticket** — 3 formative questions.
11. **Estimated time allocation** — minute-by-minute table summing to 120.

## Conventions

- Folder names `week_01`…`week_16` (zero-padded).
- Note files `lecture_01.md`…`lecture_32.md` (zero-padded, global numbering).
- Outcomes codes are authoritative in
  [../LEARNING_OUTCOMES.md](../LEARNING_OUTCOMES.md); no lecture invents its
  own codes.
- Deck conversion: decks are built *from* these files; sources for canonical
  decks will live in `../instructor/slide_sources.md`.
- Quizzes and exams reference lecture numbers exactly as titled here.
