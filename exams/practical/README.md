# Practical Coding Assessment

A 2-hour supervised lab exam at a computer. Three graded tasks, in increasing
weight: correctness first, then quality, then testing discipline.

## Format

| Task | Topic band | Marks | Suggested time |
|---|---|---|---|
| 1 | Fundamentals (validation, loops, functions) | 20 | 35 min |
| 2 | Data processing (arrays/strings) | 25 | 45 min |
| 3 | Structs or class (records/invariants) | 30 | 60 min |
| — | Test table for task 3 | 5 | within task 3 |
| | | **80** | 120 min + 20 min setup/submit |

## Rules

- Compiler command is printed on the paper; build errors are yours to fix.
- No network, no personal files. Starter skeleton provided per variant.
- Submit source only; the grader runs your file against the public sample cases
  plus hidden variants of the *same* tasks.
- Reading the task twice costs less than one rebuild cycle.

## Variants

Four equivalent variants exist (A–D). You receive one at random; all match this
format and rubric. Practice with the public tasks in the assignment sets and the
lab series — the practical reuses those skill bands, not those exact tasks.

## Grading

Per-task marks follow the shared rubric
([../../instructor/assessment-rubrics/README.md](../../instructor/assessment-rubrics/README.md)):
compiles + sample cases correct → hidden cases correct → code quality → test table.
Partial credit is generous for correct structure; it is zero for a program that
does not compile.
